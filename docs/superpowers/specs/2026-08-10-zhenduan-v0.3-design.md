# zhenduan V0.3 设计规格

## 目标
把 V0.2 的固定规则问卷升级为可实际用于 AI + FDE 首次进入商家的经营诊断工具。系统必须根据老板的真实回答和经营资料动态追问，并把“事实、假设、数据错误、经营异常”分开，不以固定答案冒充诊断。

## 核心流程
1. 老板用自然语言描述当前最头疼的经营问题。
2. AI 判断问题方向：获客、转化、复购、利润、产品、团队、渠道、数据管理等。
3. 系统根据已知信息和缺口动态追问，而不是让所有老板填写同一套问题。
4. 老板可选择上传经营资料。
5. 程序先执行确定性的数据解析、计算与审计；AI 再负责语义理解、关系分析、假设和解释。
6. 系统交叉验证老板口述与报表数据；冲突时明确提示并继续追问。
7. 输出按 P0/P1/P2 排序的经营问题与行动方案。
8. 输出诊断分析报告，并在适用时生成可下载的修正版 Excel；原文件永不覆盖。

## 诊断结论等级
- 已确认事实：有老板回答或数据直接证明。
- 高概率问题：有多项证据支持，但仍需验证。
- 待验证假设：证据不足，必须继续追问或补充数据。

每个核心问题必须包含：优先级、证据、影响、置信度、建议、具体行动、验证指标。证据不足时禁止输出确定性结论。

## 资料范围
第一阶段支持五类资料：
- 订单/销售数据
- 财务/成本报表
- 经营后台报表
- 客户/评价反馈
- 营销/投放数据

文件格式：Excel/CSV、PDF、Word、图片截图、TXT。

能力分级：Excel/CSV 做深度结构化分析；PDF/Word/TXT 做文本与指标抽取；图片做内容识别和关键指标提取，不承诺复杂表格截图达到 Excel 同等精度。

## Excel 工作簿分析
- 分析工作簿全部 Sheet。
- 识别各 Sheet 的用途与可能关系。
- 检查单 Sheet 内部问题。
- 执行跨 Sheet 核对，例如汇总营业额与订单明细合计不一致。
- 底层数据模型从第一版按 documents[] 设计，为未来多文件关联预留扩展能力。

## 数据错误与经营异常
### 数据错误
检查缺失值、重复记录、格式错误、异常负数/极端值、合计不一致、比例不合理、字段/口径冲突及可确定的公式或逻辑错误。

### 经营异常
独立识别营业额下降、毛利恶化、获客成本上涨、曝光增长但成交未增长等经营结构问题。经营异常不得被描述成“报表写错”。

## 修正原则
- 永不覆盖老板上传的原始文件。
- 确定性较高的错误可提供建议修正值。
- 无法确定的数值不得由 AI 擅自修改，标记“待确认”。
- 修正记录必须保留：原值、建议值、修改原因、置信度。

## 输出
### 诊断报告
包含报表概览、数据错误清单、经营异常、关键指标、核心经营问题、判断依据、风险/优先级、行动建议、验证指标、缺失数据。

### 可下载 Excel
保留原始数据，并新增：诊断总览、错误清单、异常清单、关键指标、修正记录、经营建议等 Sheet。未来再增加管理层 PDF 报告。

## 优先级
- P0：马上处理的严重数据或经营问题。
- P1：本周处理、对营收/利润/转化影响较大的问题。
- P2：持续优化、暂时不是主要瓶颈的问题。

## 会话与未来档案
V0.3 不要求老板注册登录。每次诊断使用独立 diagnosis_id。数据模型为未来“老板/商家 → 多次诊断 → 多份资料 → 历史指标 → 复诊 → 前后对比”预留，但本版本不增加完整账号系统。

## 架构原则
V0.3 从单文件页面升级为轻量模块化 Web App。职责至少拆分为：前端界面、问诊状态、AI 服务、文件解析、数据审计、诊断引擎、报告生成、配置。

数值计算、Excel 合计、重复检测、公式校验、同比环比等确定性任务由程序完成；AI 不作为唯一计算引擎。AI 负责语义理解、经营关系、动态追问、假设生成和解释。

继续使用 GitHub → Vercel 自动部署。线上 V0.2 在 V0.3 测试通过前保持可用；V0.3 完成验证后再替换 Production。

## 第一阶段非目标
- 不做完整用户注册/登录系统。
- 不做多商家 SaaS 权限体系。
- 不自动覆盖原始报表。
- 不承诺图片复杂表格达到原生 Excel 的解析精度。
- 不把缺少证据的 AI 推测包装为事实。
