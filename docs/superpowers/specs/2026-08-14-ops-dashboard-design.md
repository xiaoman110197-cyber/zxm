# 管理员故障面板设计

## 目标

为“老板经营问诊器”增加一个仅项目管理员可访问的故障面板，让管理员能够在不接触经营数据和上传文件内容的前提下，回答以下问题：

- 最近的文件分析和诊断请求是否成功；
- 请求失败在什么阶段、对应什么安全错误码；
- 请求总耗时和各处理阶段耗时是多少；
- 某个用户看到的请求 ID 对应哪次后台执行；
- 当前日志属于哪个部署版本，以及日志实际覆盖了多长时间。

第一版复用 Vercel Runtime Logs，不引入数据库、第三方告警系统或额外付费存储。

## 已确认范围

- 访问者：只有项目管理员本人。
- 目标留存：最多查询最近 7 天；实际范围受 Vercel 当前套餐和日志可用性限制。
- 数据范围：只处理技术元数据。
- 自动告警：第一版不提供。
- 主业务隔离：监控面板或 Vercel 日志接口不可用时，不影响文件分析、经营诊断或报告下载。

## 非目标

- 不保存或展示文件名、文件内容、OCR 原文、经营指标、诊断正文或用户身份信息。
- 不展示、记录或返回 API Key、管理员密码、Vercel Token 等秘密。
- 不建设实时告警、长期趋势仓库、用户行为分析或财务计费面板。
- 不承诺 Vercel 套餐之外的 7 天完整日志。
- 不允许通过面板修改部署、环境变量、权限或业务数据。

## 方案选择

采用“Vercel Runtime Logs 查询面板”。服务端使用只读 Vercel Token 查询部署与运行日志，将现有结构化日志聚合为管理员可读的指标。

未采用小型数据库，因为它会增加存储、清理、迁移和秘密管理工作；当前阶段先验证监控指标是否真的帮助排障。未采用 Sentry 等专业平台，因为第一版只需要现有请求链路的成功率、错误分类和耗时证据。

## 架构

### 管理员页面

- 路径：`/admin/ops`。
- 页面是独立静态外壳，不嵌入任何秘密或运行数据。
- 未认证时只显示登录表单。
- 登录后调用同源管理员 API 获取汇总和最近请求列表。
- 页面默认查询可用范围内最近 24 小时，可切换到 7 天上限。
- 页面明确显示实际最早、最晚日志时间和“数据可能不完整”的状态。

### 管理员认证

- 环境变量 `ADMIN_PASSWORD` 保存高强度管理员密码。
- 登录请求只通过 HTTPS 发送至服务端；密码不写入 URL、localStorage、日志或响应正文。
- 服务端验证成功后签发短期、HttpOnly、Secure、SameSite=Strict 的会话 Cookie。
- 会话签名使用独立环境变量 `ADMIN_SESSION_SECRET`，不复用 API Key 或业务证据签名密钥。
- 登录失败按来源执行限速；错误响应统一，不暴露账号或密码是否部分正确。
- 管理员 API 响应设置 `Cache-Control: no-store`。

### Vercel 日志读取

- 环境变量 `VERCEL_TOKEN` 仅保存在服务端，并限制为读取当前项目部署和日志所需的最小权限。
- 服务端先定位当前项目相关部署，再通过 Vercel Runtime Logs 接口读取有界日志流。
- 每次查询必须设置超时、最大部署数、最大事件数和最大响应大小。
- 只解析项目定义的结构化事件；不将任意原始日志直接返回浏览器。
- Vercel API 失败、超时或套餐限制时，API 返回安全状态和实际可用范围，不影响主业务。

## 日志事件规范

现有请求 ID 和阶段日志继续保留，但统一为单行 JSON，至少包含：

- `level`：`info` 或 `error`
- `event`：`request_started`、`stage_completed`、`request_completed`、`request_failed`
- `route`：例如 `analyze-file`、`diagnosis`、`report`
- `requestId`
- `timestamp`
- `durationMs`：完成或失败时的总耗时
- `stage`：阶段事件使用，例如 `cloud-ocr`、`structuring`、`checking-rules`
- `stageDurationMs`
- `failureCode`：仅使用允许公开给管理员的稳定错误码
- `deploymentId`、`gitSha`、`environment`

明确禁止写入：文件名、请求正文、OCR 文本、经营数值、模型原始响应、Cookie、Authorization、API Key 和管理员凭证。

## 面板内容

### 状态摘要

- 实际日志覆盖时间
- 当前/最近部署 Git SHA
- 请求总数
- 成功数与失败数
- 成功率
- 平均总耗时与 P95 总耗时

### 错误分布

- 按稳定 `failureCode` 聚合次数和占比
- 按路由聚合失败数
- 不显示供应商原始错误正文

### 阶段耗时

- 文件接收与解析
- 云端 OCR
- 结构化
- 确定性规则检查
- 诊断主模型与复核
- 报告生成

每个阶段显示样本量、平均耗时和 P95；无数据时明确显示“无样本”。

### 最近请求

- 时间
- 路由
- 请求 ID
- 成功/失败
- 总耗时
- 最后完成阶段或失败阶段
- 安全错误码
- 部署短 SHA

支持按请求 ID 精确筛选，但不提供全文日志浏览器。

## 数据流

1. 业务 API 在关键阶段输出安全的单行 JSON 日志。
2. Vercel 保存 Runtime Logs，留存能力由当前套餐决定。
3. 管理员登录 `/admin/ops`。
4. 管理员 API 验证会话并从 Vercel 拉取有界日志。
5. 服务端解析允许的事件，按请求 ID 聚合并计算指标。
6. 浏览器只接收汇总结果和安全技术元数据。

## 错误处理

- 缺少管理员配置：管理员接口返回 503，主业务保持可用。
- 未登录或会话过期：返回 401，页面回到登录状态。
- 登录失败过多：返回 429，并提供安全的稍后重试提示。
- Vercel Token 无效或权限不足：显示“监控数据暂不可用”，不返回上游正文。
- 日志查询超时或截断：返回已有聚合，并标记 `partial=true` 与实际覆盖时间。
- 无日志：显示空状态，不把“无数据”解释为“系统无故障”。
- 解析到未知或不合规日志：忽略该事件并记录安全计数，不返回原文。

## 安全与隐私

- 管理员页面和 API 均禁止缓存、禁止搜索引擎索引。
- 所有秘密只在服务端读取。
- 密码比较使用抗时序攻击的固定长度摘要比较。
- 会话有固定短期有效期，不提供永久登录。
- 日志事件采用字段白名单，服务端输出再次采用字段白名单。
- 单个请求 ID 不得反查业务数据。
- 测试必须验证常见秘密格式和业务样例不会出现在日志、HTML 或 API 响应中。

## 测试策略

### 单元测试

- 结构化日志生成器只输出白名单字段。
- 日志解析器拒绝未知、超长和包含敏感字段的事件。
- 请求聚合正确计算成功率、平均值、P95、错误分布和阶段耗时。
- 查询范围被限制在最多 7 天，并正确报告实际覆盖时间。
- 会话签发、验证、过期和篡改检测正确。

### API 测试

- 未认证访问被拒绝。
- 登录成功设置安全 Cookie；失败限速生效。
- 管理员 API 不缓存、不泄露 Token 或原始日志。
- Vercel API 失败、超时、空结果和截断均返回安全且明确的状态。

### UI 测试

- 未登录只显示登录界面。
- 已登录显示摘要、错误分布、阶段耗时和最近请求。
- 部分日志和无日志状态不会显示虚假的 100% 健康。
- 手机和桌面宽度均无横向溢出。

### 回归验证

- 完整现有测试继续通过。
- `main` Preview 健康检查、文件上传、OCR、结构化、规则检查和诊断流程不受管理员面板故障影响。

## 验收标准

1. 未认证访问不能获得任何监控数据。
2. 管理员密码、会话密钥和 Vercel Token 不出现在客户端、日志或接口响应。
3. 可以按请求 ID 查看一次请求的路由、阶段、结果和耗时。
4. 可以查看成功率、错误码分布、总耗时和阶段耗时。
5. 页面明确显示实际日志覆盖时间与完整性状态。
6. 面板不保存或显示文件名、OCR 内容和经营数据。
7. Vercel 日志不可用时主业务正常运行。
8. 完整自动测试和部署检查通过。

## 后续升级条件

只有出现以下任一情况时，再评估数据库或专业监控平台：

- Vercel 套餐日志留存不足，且真实排障连续需要更长历史；
- 需要自动告警或跨部署长期趋势；
- 监控数据量使实时日志聚合明显变慢；
- 多位管理员需要细粒度账号、审计或权限控制。
