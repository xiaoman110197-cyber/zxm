# zhenduan V0.3 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可测试的 V0.3 模块化基础，先完成动态问诊与 Excel 多 Sheet 审计/报告闭环，再逐步接入其余文件格式，避免一次性把多个独立子系统混在一起开发。

**Architecture:** 前端只负责会话与展示；服务端 API 负责 AI 调用、文件解析与报告生成；确定性审计引擎与 AI 诊断引擎分离。所有诊断围绕 diagnosis_id 和 documents[] 数据模型运行，V0.2 Production 在 V0.3 验证前不被替换。

**Tech Stack:** Vercel Web App / Node.js serverless API / browser frontend / SheetJS-compatible Excel parsing and generation / OpenAI API via server-side environment variable / Vitest-style unit tests.

## Global Constraints
- 不覆盖原始上传文件。
- Excel 第一阶段必须分析全部 Sheet 并支持跨 Sheet 核对。
- 确定性计算由程序完成，AI 不作为唯一计算引擎。
- AI 结论区分已确认事实、高概率问题、待验证假设。
- 每个核心问题输出 P0/P1/P2、证据、影响、置信度、行动与验证指标。
- V0.3 验证通过前不替换线上 V0.2 Production。
- V0.3 不实现完整账号/登录或多商家 SaaS 权限体系。

---

## 文件结构
- `package.json`：依赖、开发与测试命令。
- `src/domain/diagnosis.js`：diagnosis_id、回答、证据、结论的数据模型与验证。
- `src/diagnosis/question-engine.js`：根据当前证据和缺口决定下一问题。
- `src/diagnosis/prioritize.js`：P0/P1/P2 与置信度规则。
- `src/audit/workbook.js`：Excel 全 Sheet 读取、类型推断和工作簿模型。
- `src/audit/rules.js`：缺失、重复、格式、合计/跨 Sheet 等确定性规则。
- `src/reports/workbook-report.js`：生成不覆盖原数据的分析/修正版工作簿。
- `api/diagnosis.js`：服务端 AI 诊断接口；密钥只从环境变量读取。
- `api/analyze-file.js`：文件上传、解析、审计入口。
- `public/index.html`、`public/app.js`、`public/styles.css`：移动端问诊 UI。
- `tests/`：对应领域、问诊、审计和报告测试。
