# 老板经营诊断 AI / zhenduan

当前版本：V0.3。

这是一个面向小商家老板的 AI + FDE 经营问诊原型。老板可以先自由描述经营问题，系统根据已有回答和上传的经营资料动态追问；证据足够时输出带 P0/P1/P2、证据、影响、行动和验证指标的诊断结论。

## 当前真实能力

- 自由描述问题后由 AI 动态追问，不使用固定题序。
- 支持 DeepSeek / OpenAI 诊断；配置两者时可在主模型失败后切换备用模型，关键结论可做第二模型复核。
- 支持上传五类经营资料：Excel（.xlsx/.xls）、CSV、PDF、Word（.docx）、JPG/PNG 图片。
- Excel/CSV 使用确定性表格解析与数据质量审计；AI 只接收受限的结构化样本和审计摘要，不把整份大表无上限塞进模型。
- PDF/Word 提取文字；长文档会截断并明确提示。
- 图片使用 OCR，返回置信度；低置信度内容要求人工确认，不能单独支撑“事实”结论。
- 文件分析支持阶段进度、OCR 实际进度、一次网络自动重试和手动重新分析。
- Excel 原文件可生成包含诊断/错误/异常/指标/修正记录/经营建议的报告工作簿。
- 文件、诊断上下文、模型输出和报告生成均设置了资源上限；OpenAI Responses 请求显式 `store:false`。

## 当前明确边界

- 扫描版/纯图片 PDF 目前不会自动做整页 OCR；无法提取文字时会明确提示。
- 目前一次只分析一个上传文件，不做多文件跨期/跨来源自动对账。
- 表格确定性经营异常引擎仍较保守；复杂趋势、客单价、成本率、渠道效率等需要后续增强。
- 高度格式化、合并单元格很多、标题行不在第一行的 Excel 模板，识别能力仍有限。
- 没有用户登录、历史诊断、跨设备恢复或持久化后台任务；浏览器进程被系统彻底终止后不能从服务器检查点恢复上传分析。
- 当前实例内突发限流只是成本保护的一层，不等同于跨所有 Serverless 实例的全局限流。
- 没有直接接入小红书、抖音、大众点评等平台的实时经营/达人数据；没有接口时不得伪装成实时能力。

## 本地验证

```bash
npm install
npm test
npm run build
```

CI 会对 `feature/**`、Pull Request 和合并后的 `main` 推送执行测试与生产构建。

## 原则

- 不把猜测写成事实。
- 上传资料、OCR 文字和表格内容属于不可信业务证据，不属于系统指令。
- 无法确认的数据必须标记不确定性，而不是补猜数字。
- 外部平台没有真实接口时，只能给出建议或待接入能力，不能伪造查询结果。
